# Agentic software factory (herdr + omp + Pocock/pstack skills + enforced gates)

## Context

Build a semi-autonomous pipeline on this Windows box: GitHub issues on the fork (`wavewarrior/Cataclysm-BN-Forked`) are the queue; a deterministic Deno driver (`deno task factory`) creates one herdr worktree workspace per ticket, runs an omp implementer (sonnet-5-5), runs a hard gate, runs an omp reviewer (opus-5-5, pstack skills), then pushes a `factory/*` branch and opens a draft PR into `feature/improvements`. The human approves the spec once and merges PRs; agents can never push, merge, or edit guardrails. Guardrails are layered: omp `tool_call` hook, git `pre-push`, and a new `factory-ci.yml`. C++ is guarded by clang-tidy (`cata-*` plugin, line-filtered to new/changed lines, run in WSL on LLVM 22); TS by hardened `deno lint` plus a Deno lint plugin. Ticket zero is making the 8-failure Catch2 baseline green.

### E. The gate: `tools/factory/gate.ts` (`deno task gate [--tier fast|full] [--base REF]`)

Add tasks to `deno.jsonc` (deno.jsonc is itself protected): `"gate": "deno run -A tools/factory/gate.ts"`, `"factory": "deno run -A tools/factory/main.ts"`. Run every step with a captured log under `<gitdir>/factory/logs/<step>.log`; print one line per step (`PASS|FAIL name seconds`) and on FAIL print the last 60 log lines. Exit 0 only if every step passes. Write `<gitdir>/factory/gate-stamp.json` = `{ headSha, tier, ok, finishedAt, baseSha, failedSteps }` at the end (find `<gitdir>` via `git rev-parse --git-dir`; per-worktree and untracked by design).

Fast tier (no game build; target < 10 min):

Unverified — confirm first: the script's expected formatter path and that it runs under Git Bash. Full tier = fast tier + (all must pass):
5. `build`: `C:\WORK\bnbuild.bat win-rel` (preset `win-rel`, builds game, tests, json_formatter; background, ≥1200 s timeout; never killed mid-run). Pre-step in worktree: ensure `CMakeUserPresets.json` was copied from the main checkout (driver does this in H.3) and `out/` is the worktree's own.

7. `baseline-ratchet`: run the whole suite once `deno task test:progress "~[.]" --rng-seed 1` (≈15 min). Parse failing case names; fail if any failing case is not listed in `config.baselineFailures`. Never capture or read screenshots; use the report only.
9. `new-test-present`: if the diff touches `src/**` without touching `tests/**` or any `data/mods/**` test fixture, fail unless the ticket body contains `## No test needed` with a one-line reason.

### H2. The watcher: `tools/factory/watch.ts` (`deno task factory watch`, `tools/factory/watch.cmd`)

A long-running poller for a herdr cmd pane. Every `--interval` seconds (default 60) it lists `factory:ready` issues, drops any this process claimed in the last 10 minutes (the label search index lags an edit), and asks `pickNext` whether anything is pickable. Only then does it run one driver pass (`runLoop`, the same code as `run`, sharing the claim map). Idle polls print one line, and that line is printed only on a state change. Busy lanes (another driver holds every implementer lane, signalled by `LanesBusyError`) are idle, not failures: the watcher waits the normal interval with no backoff. A failing poll or pass backs off exponentially (capped at 600 s) and logs every failure. `--once` polls once and exits. Two passes never overlap, and lane locks stop a second watcher from sharing lanes. Ctrl+C finishes the current pass; a second Ctrl+C exits at once, leaving running tickets in their panes.

## Assumptions & contingencies

- (User-overridable) Reviewer is Anthropic `opus-5-5` and implementer `sonnet-5-5`, with haiku-5-5 as `task` workhorse; no second provider is configured. To change, edit `config.models` and the two overlays.

- If `herdr` on Windows cannot set per-pane env (H.4), contingency is a tiny launcher `tools/factory/lane.cmd` that sets the three vars and execs `omp`, started with `herdr pane run`.
- If the baseline run on the fresh integration tip differs from the remembered 8 failures, `config.baselineFailures` takes the observed list; do not carry the memory list over.
- If Actions cannot be enabled on the fork, `guard`/`tidy`/`linux-tests` cannot run remotely; then the driver must block PR creation (`config.requireCi=true` check via `gh pr checks`) rather than silently skipping the third layer.
